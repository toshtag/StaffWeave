# 移行の確認に使う代表データ

`scripts/verify-upgrade.sh` が使います。

## 何のためにあるか

あとから足した migration を、既にデータのあるデータベースへ当てられるかを確かめます。

空のテーブルでは分かりません。列を足すときの `NOT NULL`、値の範囲を狭める検査、
期間の重なりを禁じる制約は、行が無ければ必ず通ります。

## 支える起点

いまは **0025** です。0025 まで当たっているデータベースから、
最新までを順に当てられることを確かめています。

起点より前の版からの移行は確かめていません。

## 起点を上げるとき

古い版を支え続けると、確認に使うデータが実際の利用者と合わなくなります。
支える範囲を狭めるのは、次の順で行います。

1. `verify-upgrade.sh` の `BASELINE` を新しい番号にする
2. このディレクトリのファイル名を `<新しい番号>-baseline.sql` へ変える
3. 中身を、その版の時点で作れる形に直す
   - あとの版で足した列や表を使うと、起点の再現になりません
4. `docs/operations/deployment.md` の「支える移行の起点」を直す
5. `./scripts/verify-upgrade.sh` を動かして通ることを見る

起点を上げる前に、それより古い版を使っている利用者が居ないかを確かめてください。
確かめずに上げると、上げた版より古い利用者は移行できなくなります。
