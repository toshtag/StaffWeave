# StaffWeave

勤怠管理のシステムです。SaaS ではなく、自分たちのサーバーに置いて動かします。
リリース候補です。実機・第三者・試行運用の確認が済んでいないため、正式リリースはしていません。

出勤・退勤の打刻から、勤務時間の計算、申請と承認、月末の締めまでを扱います。
打刻はブラウザとスマートフォンから行えます。

据え置きの打刻端末と IC カードは、サーバー側の取り決めと、端末で常駐する側まで動きます。
送れなかった打刻はディスクへ残し、回線が戻ってから順に送ります。
配布物は、リポジトリを持たない端末でそのまま動く形で作れます。

実機の読み取り装置と、Windows のサービスとしての起動は確かめていません。
確かめる項目は [device-agent-service.md](docs/operations/device-agent-service.md) にあります。
PC のログイン・ログオフの記録も、送られてくれば取り込めますが、
これで勤務時間を決めることはしません。打刻とずれていたら本人と管理者に見せるだけです。

打刻した記録は書き換えません。時刻を直すときは、元の記録を残したまま訂正を足します。
あとから「誰がいつ何を直したか」を辿れます。

計算できるのは、実労働、休憩、所定の時間帯の内外、深夜帯、休日労働、
法定内と法定外、法定休日と法定外休日、遅刻・早退、みなし時間です。
通常・フレックス・裁量・変形の労働形態を、期間つきで割り当てられます。

労務計算の値は、法令上の普遍的な既定値として持ちません。事業者が設定します。
設定しないまま計算が進むと、誰も決めていない値が結果として残ります。
未設定の区分は 0 ではなく「未設定」として示します。

休暇は、付与・取得・失効・手当て・取消を追記で積む台帳で持ちます。
残数は保存せず、任意の時点の値を台帳から組み立てます。

申請は種別を組織が定義し、1〜4 段の承認、差し戻し、出し直し、取消、代理を通せます。

月次は日次から導き、締めた時点の値を別に固めます。
締めたあとに訂正しても、給与へ渡した値は動きません。

画面は、打刻、当日の勤怠と訂正、承認待ち、異常と差異、API キー、自分のセッションに加えて、
組織・拠点・部門・従業員・閲覧範囲・勤務区分・計算規則・労働形態・休暇種別・休暇台帳・
申請種別・月次を設定する画面が動きます。

何ができて何ができないかは
[capability-matrix.md](docs/product/capability-matrix.md) に 1 行ずつ書いてあります。
この README と食い違ったときは、そちらが正本です。

## 動かしてみる

Node.js 22.12 以上、pnpm 11、Docker が要ります。

```sh
pnpm install
cp .env.example .env
docker compose up -d db                             # PostgreSQL
pnpm db:migrate
pnpm bootstrap --email admin@example.com            # 最初の管理者。パスワードは一度だけ表示
pnpm dev                                            # API 8787 / 画面 5173
```

`pnpm seed:demo` で架空のデータが入り、ひととおりの画面を見られます。
Docker だけで動かす場合や、初期パスワードを自分で決める場合は
[getting-started.md](docs/guide/getting-started.md) を見てください。
