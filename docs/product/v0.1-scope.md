# v0.1 に入れるもの

正式リリースの 1 回目（v0.1）で、何を必須とし、何を次期へ回すかを決めます。

決めておかないと、`planned` が 1 件でも残っているかぎり
「まだ完成していない」と言い続けることになります。
すべてを作り終えてから出す、という進め方は、いつまでも出さないことと同じです。

判断の基準は 1 つです。**これが無いと、導入した組織が業務を回せないか。**
無くても回せるなら、v0.1 には入れません。

## 必須（v0.1 に入れる）

すべて実装済みです。

| 要るもの | 無いとどうなるか |
| --- | --- |
| 打刻・訂正・日次の計算 | 勤怠を記録できない |
| 申請と承認、月次の締め | 勤怠を確定できない |
| 締めた時点の値の固定 | 給与へ渡した値を、あとから説明できない |
| 休暇の台帳 | 残数を別の帳簿で管理することになる |
| 設定の画面 | 導入時に SQL を書くことになる |
| 給与連携の出力 | 手で転記することになる |
| バックアップと復元 | 事故から戻せない |
| 管理者による利用者のセッション失効 | 退職・端末の紛失に対応できない |
| 管理者によるパスワードの再設定 | 本人が入れなくなったとき復旧できない |
| 監査記録 | 誰が何を変えたかを説明できない |
| 稼働の確認（`/api/health`・`/api/ready`） | 落ちていることに気付けない |

## 次期へ回すもの

無くても業務は回ります。回し方を運用の手順で補います。

| 回すもの | v0.1 でどう回すか |
| --- | --- |
| 招待・パスワード再設定の自己申請 | 管理者が作り、初回のパスワードを渡す。忘れたら管理者が再設定する |
| MFA・SSO | パスワードとログインの回数制限で守る。外部の認証基盤とは繋がない |
| メトリクスとアラート | 1 行 1 件の構造化ログを、既存のログ基盤で拾う |
| データの保持と自動の削除 | 方針を決め、手で行う（[retention.md](../operations/retention.md)） |
| 行単位の権限（Row-Level Security） | 閲覧範囲をアプリケーションで判断する。境界は統合テストで固定する |
| 端末の自動更新 | 配布物を置き直す |

## この一覧の扱い

ここに書いた「次期へ回すもの」は、
[capability-matrix.md](capability-matrix.md) では `planned` のままです。

作っていないものを `implemented` にはしません。
v0.1 に要らないと決めたことと、作ってあることは別です。

一覧を変えるときは、上の基準（無いと業務が回らないか）に照らして判断してください。
