# 勤務予定・勤務区分・労働形態の優先順位

勤務パターン・勤務予定・勤務区分は、どれも所定時刻や休憩を持てる。
みなし労働分数は、勤務区分と労働形態の両方が持てる。
同じ意味の値が複数の場所にあると、計算がどれを読んだのかを結果から言えなくなる。
ここで正本と順位を 1 つに決める。

## 役割

| 対象 | 持つもの | 役割 |
| --- | --- | --- |
| 勤務パターン | 始業・終業・休憩の合計分数 | 所定時刻のひな形。従業員も日付も持たない |
| 勤務区分 | 所定時刻、固定休憩、自動休憩、みなし、深夜帯の上書き、中抜けの扱い、日種別、表示 | 働き方の定義。適用開始日で版を重ねる |
| 勤務予定 | その従業員・その業務日の所定時刻、休憩分数、日種別、勤務パターン、勤務区分 | その 1 日に確定した予定 |
| 労働形態の割当 | 制度の種別、清算期間（月数・起算日・総枠・決め方）、コア/フレキシブルの帯、みなし | その従業員へ適用している制度。有効日で切り替える |

## 決め方

**所定時刻・休憩分数・日種別は、勤務予定を正本にする。**

勤務予定は登録の時点で値を確定させる。ひな形から埋める順は次のとおりで、
後のものが前のものを上書きする。

1. 勤務区分の所定時刻（`scheduledStartMinutes` / `scheduledEndMinutes`）
2. 勤務パターンの始業・終業・休憩
3. 要求で明示された値

確定した値は `work_schedules` の行に残る。あとで勤務区分やパターンを直しても、
すでに登録した予定は変わらない。予定を直すのは、予定そのものを登録し直したときだけ。

**固定休憩・自動休憩・みなし・深夜帯の上書き・中抜けの扱いは、勤務区分を正本にする。**

これらは勤務予定にも勤務パターンにも置き場が無い。計算のときに、勤務予定が指す
`work_category_id` から、その業務日に効いている版を読んで使う。

**みなし労働分数は、裁量労働の割当が効いている日だけ労働形態を正本にする。**

裁量のみなしは、その人との取り決めで決まる値であり、日ごとに差し替わる
勤務区分より後から動かない。裁量の割当が無い日、または裁量以外の制度の日は、
勤務区分の値を使う。

労働形態の割当のうち、日次の計算が見るのはみなし労働分数だけ。
清算期間とコア/フレキシブルの帯は日をまたぐ枠なので、期間の集計側が扱う。

## 版の選び方

勤務予定が持つのは、割り当てた時点の版の id。勤務区分は `code` ごとに
期間を分けて版を重ねるため、対象日には別の版が効いていることがある。

計算は id から `code` を辿り、`effective_from <= 業務日 <= effective_to` を
満たす版を選ぶ。満たす版が無ければ、勤務区分は無いものとして計算する。

割当の時点でも同じ判定をする。対象日に効いていない版は勤務予定へ入れられない。
入れられると、登録は成功したのに計算では解決できない、という状態が残る。

## 勤務区分を持たない予定

`work_category_id` が空の予定は、これまでどおり勤務予定の所定時刻と
休憩分数だけで計算する。固定休憩も自動休憩も深夜帯の上書きも効かない。

既存の予定へ勤務区分をさかのぼって埋めることはしない。
埋めると、誰も決めていない区分で過去の集計が変わる。
過去へ効かせたい場合は、その期間の予定を登録し直す。

## 指紋への入れ方

計算の入力の指紋には、勤務区分のうち計算へ効く値だけを入れる
（`code`、固定休憩、自動休憩、深夜帯の上書き、中抜けの扱い、みなし）。
労働形態からは制度の種別とみなし労働分数を入れる。

表示名・色・シフト属性は入れない。入れると、結果が変わらない編集でも
計算の版が増え、履歴から本当の変更を追えなくなる。
