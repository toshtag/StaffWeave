# IC カードの指紋鍵

IC カードの生の識別子は保存しません。保存するのは、鍵付きの一方向変換で作った指紋だけです。
守れているかどうかは鍵の扱いで決まるため、ここで前提を固定します。

実装は `packages/api/src/config.ts`、
`packages/api/src/shared/security/card-fingerprint-key.ts`、
`packages/agent/src/card/reader.ts` にあります。

## 鍵は 2 段になっている

| 名前 | 場所 | 役割 |
| --- | --- | --- |
| 共通の鍵 | サーバーの環境変数 `CARD_FINGERPRINT_KEY` | Workspace ごとの鍵を導く元 |
| Workspace の鍵 | 端末の資格情報ファイル | カードの指紋を計算する |

端末へ渡すのは Workspace の鍵だけで、共通の鍵は渡しません。
導出は端末を登録した時点で行い、その端末が属する Workspace のものに限ります。

```text
Workspace の鍵 = HMAC-SHA256(共通の鍵, "staffweave-card-fingerprint/1:<workspaceId>") の 16 進数
指紋           = HMAC-SHA256(Workspace の鍵, 大文字にしたカード識別子) の 16 進数
```

共通の鍵をそのまま配ると、ある Workspace で端末を登録できる者が、
他の Workspace のカード指紋を計算して照合できます。指紋は Workspace ごとに保存しているため、
鍵も同じ単位で分けます。

## 設定

```sh
openssl rand -hex 32
```

- 32 文字未満の値では API は起動しません。
- 空文字と空白だけの値は未設定として扱います。
- `.env.example` が配っていた見本の値は鍵として受け付けません。
- `docker-compose.yml` は既定値を持ちません。ホスト側に設定があるときだけ渡します。

## 未設定のときの動作

共通の鍵が無い構成では、IC カードの経路をすべて 404 で断ります。

| 経路 | 未設定のときの応答 |
| --- | --- |
| `GET /api/card-credentials` | 404 `IC カード機能は設定されていません` |
| `POST /api/card-credentials/registrations` | 同上 |
| `POST /api/card-credentials/{cardCredentialId}/revoke` | 同上 |
| `POST /api/device-agent/card-credentials` | 同上 |
| `POST /api/device-agent/card-events` | 同上 |

端末の登録（`POST /api/device-agent/enroll`）は成功しますが、応答に鍵は含まれません。
Agent はカードの操作を実行前に断ります。

鍵なしで計算した指紋は、カード識別子そのもののハッシュと変わらず、
誰でも同じ値を計算できます。受け取らないことで、
「生のカード識別子をそのまま保存しない」という取り決めを保ちます。

## 鍵を変えたとき

共通の鍵を変えると、Workspace の鍵も、そこから作る指紋もすべて変わります。

- 登録済みのカードは、どれも一致しなくなります。
- 端末の資格情報ファイルには古い鍵が残るため、端末を登録し直します。
- カードは失効させたうえで、登録トークンを発行して登録し直します。
- 打刻の記録は残ります。失われるのは「どのカードがどの従業員か」の対応だけです。

同じ鍵へ戻せば元の指紋に戻ります。値そのものの控えを安全に保管してください。

## 機密区分

| 場所 | 共通の鍵 | Workspace の鍵 |
| --- | --- | --- |
| サーバーの環境変数 | 含まれる | 含まれない |
| データベース | 含まれない | 含まれない |
| `pnpm backup` の出力 | 含まれない | 含まれない |
| API の応答 | 含まれない | 端末の登録時だけ返る |
| Agent の資格情報ファイル | 含まれない | 含まれる |
| ログ | 含まれない | 含まれない |

バックアップには鍵が含まれません。復元しただけではカードの照合はできず、
同じ共通の鍵を環境変数へ設定する必要があります。

## 現在の限界

- 鍵の入れ替え手順は手作業です。自動化した移行はありません。
- 端末が持つ Workspace の鍵を、端末の失効に合わせて無効化する仕組みはありません。
  端末を失効させても、その端末が保持している鍵の値は変わりません。
- 指紋から従業員を辿れるのはデータベースの中だけですが、
  同じカードを別の Workspace で使っても、指紋が違うため同一とは分かりません。
