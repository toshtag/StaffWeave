# 認証とセッション

パスワードの変更、セッションの有効期間、ログイン試行の制限をまとめます。
ブラウザからの要求に対する検査（`Origin`・応答ヘッダー・本文の上限）は
[http-hardening.md](http-hardening.md) にあります。

## パスワードの変更

ログインした本人が、画面の「パスワードの変更」から自分のパスワードを変えられます。
`POST /api/auth/password` でも同じことができます。

- 現在のパスワードの確認を必須にします。Cookie だけでは変えられません。
- 新しいパスワードには、登録時と同じ強度の条件を適用します。
- 変更すると、その端末以外のセッションはすべて失効します。
  漏れたパスワードで開かれたセッションを残さないためです。
- 監査記録には、変更が行われた事実と失効したセッションの件数だけを残します。
  古い値も新しい値も残しません。

初期化時に表示されたパスワードは、この経路で変えてください。

## セッションの有効期間

セッションには 2 つの期限があります。どちらもサーバーが判定します。

| 期限 | 既定 | 延長 |
| --- | --- | --- |
| アイドル期限 | 最後の利用から 12 時間 | 残りが半分を切ると、その時点から数え直す |
| 絶対期限 | 発行から 7 日 | 延びない |

- 操作を続けているあいだはアイドル期限が延びますが、絶対期限は動きません。
  発行から 7 日を過ぎたセッションは、直前まで使われていても断ります。
- 盗まれたトークンを使い続けるかぎり終わらない状態を作らないための上限です。
- セッション Cookie の保持期間は絶対期限に合わせます。
  アイドル期限に合わせると、サーバーが延長したセッションがブラウザからだけ消えます。
- 絶対期限は保存している発行時刻から決まります。すでに発行済みのセッションにも、
  移行を待たずに同じ上限が効きます。

## ログイン中の端末

ログインした本人が、画面の「ログイン中の端末」で自分のセッションを一覧し、
終わらせられます。`GET /api/auth/sessions`、`DELETE /api/auth/sessions/{sessionId}`、
`POST /api/auth/sessions/revoke-others` でも同じことができます。

- 見えるのも終わらせられるのも本人の分だけです。他の利用者や他のワークスペースの
  セッションは、識別子を知っていても一覧に出ず、終わらせられません。
- 他人のセッションの識別子を指定した場合と、存在しない識別子を指定した場合の応答は
  同じです。応答の違いから、そのセッションがあるかどうかを確かめられないようにします。
- いま使っているセッションは、この経路では終わらせません。一覧から消すと画面は
  残ったまま次の要求で断られます。手元を終わらせるのはログアウトです。
- 監査記録には、失効させた事実と件数だけを残します
  （`auth.session_revoked`、`auth.other_sessions_revoked`）。

管理者が他の利用者のセッションを終わらせる経路はありません。

### 端末の見分け方

一覧に手掛かりが無いと、覚えのないセッションだけを選んで終わらせられません。
そこで、ログインした端末の系統だけを保存します。

| 保存するもの | 例 |
| --- | --- |
| OS の系統 | `windows`、`macos`、`ios`、`ipados`、`android`、`chromeos`、`linux` |
| ブラウザの系統 | `chrome`、`safari`、`firefox`、`edge`、`opera`、`samsung` |
| 端末の種別 | `desktop`、`mobile`、`tablet` |

- 生の `User-Agent` は保存しません。版番号と端末の型番が入るためです。
- 送信元アドレスも保存しません。回線で変わるため端末の判別には弱く、
  その一方で居場所に繋がります。ログイン試行を数える用途には使いますが、残しません。
- 判別できない項目は空にします。判別できなくてもログインは断りません。
  見慣れない端末から入れなくなる理由が、名乗り方だけになってはいけないためです。
- この列を持つ前に開いたセッションは「端末情報なし」と表示します。
  保存していない名乗りを、こちらの推測で埋め戻しません。
- iPadOS の Safari は既定で Macintosh を名乗るため、パソコンとして表示されます。
  名乗りの上で区別できないものを、こちら側の推測で分けません。
- 表示に使う文字列は画面が言語ごとに決めます。保存するのは上の系統だけです。

## ログイン試行の制限

ログインの失敗を数え、続いたら受け付けを断ります。断っているあいだは
パスワードの照合そのものを行いません。誤ったパスワードを送るだけで
計算資源を使わせられる状態にしないためです。

| 設定 | 既定 | 数える単位 |
| --- | --- | --- |
| `LOGIN_MAX_FAILURES_PER_ACCOUNT` | 5 | ワークスペースと利用者の組 |
| `LOGIN_MAX_FAILURES_PER_SOURCE` | 50 | 送信元アドレス |
| `LOGIN_FAILURE_WINDOW_MS` | 15 分 | 数え直すまでの時間 |
| `LOGIN_BLOCK_MS` | 15 分 | 断る時間 |

- 断られたことは応答から区別できません。登録の有無を漏らさないためです。
  断ったことはログ（`auth.login_blocked`）に残ります
- 入れたら、その利用者の失敗の記録は消えます。送信元の記録は残ります
- 送信元は接続元のアドレスから決めます。前段の逆プロキシが `X-Forwarded-For` を
  必ず書き換える構成では `TRUST_PROXY_FOR_CLIENT_ADDRESS=true` にしてください。
  直接受ける構成で有効にすると、送信元を自由に名乗れて数える意味がなくなります
- 送信元が分からない場合は、その要求を送信元では数えません（利用者ごとの制限は効きます）
