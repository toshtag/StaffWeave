## 2. 凍結の範囲

候補を止めている間、main へ入れてよいのは次だけです。

- 外部の確認で見つかった、重大・高リスクの修正
- リリースを妨げる不具合の修正
- 文書の誤りの訂正

**新しい機能は入れません。**

入れたくなったら、それは v0.1 に要るものだったということです。
[product/v0.1-scope.md](../product/v0.1-scope.md) の判断が間違っていたことになるので、
機能を足す前に、その文書を直してください。

## 3. 外部の確認

3 つを並行して進めます。手順と記録欄は [checklist.md](checklist.md) の 4 章です。

| 確認 | 状態 |
| --- | --- |
| 実機の打刻端末 | 未実施 |
| 第三者によるセキュリティ確認 | 未実施 |
| 試行運用（1 か月） | 未実施 |

見つかったものは、その場で直さずに Issue へ貯めます。
1 件ごとに直すと、そのたびに候補が変わり、確認をやり直すことになります。

## 4. 候補が変わるとき

重大・高リスクの修正を入れると、候補の commit は別のものになります。

そのとき、古い候補で得た確認の結果を、そのまま新しい候補の結果として使えません。
何を直したかによって、やり直す範囲が変わります。

| 直したもの | やり直すもの |
| --- | --- |
| 端末・Agent・登録 | 実機の確認 |
| 認証・認可・秘密情報・外部へ出る経路 | 第三者の確認 |
| 打刻・申請・承認・締め・給与への引き渡し | 試行運用のうち、その経路 |
| 上記に触れない文書だけ | なし |

やり直す範囲を決めたら、この文書の 1 章と 3 章を新しい候補で書き直します。

## 5. 正式リリースの判断

3 つの確認がすべて済み、重大・高リスクの Issue が 0 になったら、
最後の候補で次を実行します。

```sh
pnpm verify:release-candidate
pnpm release:manifest
```

揃えるものは [checklist.md](checklist.md) の 6 章にあります。

タグと署名は、そのあとに所有者が決めます。この手順では行いません。
