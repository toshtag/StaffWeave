# 決定の記録

「なぜそうなっているのか」がコードを読んでも分からない判断を、ここに残します。
事業上の判断、変えるのに手続きが要るもの、選ばなかった案に意味があるものが対象です。

結果を見れば分かることは書きません。`LICENSE` を開けば MIT License だと分かるので、
それを選んだ記録は要りません。データベースの並びのように、`docker-compose.yml` を見ても
「なぜその値なのか」が出てこないものだけを残します。

実装の判断も書きません。Issue と PR で追えます。
守るべき原則は `docs/` の他の文書に、いま作っているものは GitHub にあります。

## 書き方

ファイル名は `<4 桁の番号>-<短い名前>.md`。番号は使い回しません。
中身は次の見出しで書きます。

```text
## 状態
## 背景
## 決定
## 影響
## 見直す条件
```

一度書いた決定は書き換えません。判断が変わったら新しい番号で足し、
古いほうの「状態」に後継を書きます。消してしまうと、
そのとき何を根拠にしたのかが分からなくなります。

## 一覧

| 番号 | 決定 |
| --- | --- |
| [0003](0003-database-collation.md) | データベースの並びを libc から切り離し、基盤に Debian を使う |

0001（MIT License の採用）と 0002（著作権表示の名義）は消しました。
どちらも `LICENSE` を開けば分かることで、記録として残す意味がありませんでした。
番号は空いたままにします。使い回すと、過去のコミットが指す番号と食い違います。
