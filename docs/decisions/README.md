# 決定の記録

後から「なぜそうなっているのか」を確かめるために、
実装だけでは読み取れない判断をここへ残します。

対象にするのは、次のどれかに当てはまる判断です。

- 事業上の判断であり、コードからは導けないもの
- 一度決めると変更に手続きが要るもの
- 複数の選択肢があり、選ばなかった理由に意味があるもの

対象にしないもの。

- Issue と PR で追える実装の判断
- 恒久的な原則（`docs/` の他の文書が正本）
- 進行状態

## 書式

ファイル名は `<4 桁の番号>-<短い名前>.md` とし、番号は再利用しません。
中身は次の見出しで書きます。

```text
## 状態
## 背景
## 決定
## 影響
## 見直す条件
```

一度記録した決定は書き換えません。判断が変わった場合は、新しい番号で追加し、
古いほうの「状態」へ後継を書きます。過去の判断を消すと、
そのとき何を根拠にしたのかが追えなくなります。
