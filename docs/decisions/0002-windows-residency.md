# 0002 Windows での常駐を、サービスではなくタスクスケジューラで行う

## 状態

確定（2026-08-07）

## 背景

据え置きの打刻端末は、電源を入れたら人が何もしなくても打刻を受け付け続ける必要があります。
Windows でこれを実現する方法として、配布物には次を入れていました。

```powershell
sc.exe create StaffWeaveAgent binPath= "node.exe agent\cli.js station --store ..."
```

これは動きません。Windows のサービスとして登録されるプロセスは、Service Control Manager
（SCM）と話す入口を持っている必要があります（`StartServiceCtrlDispatcher`、ServiceMain、
制御ハンドラ）。`node.exe` も私たちの `cli.js` も、それを実装していません。

`sc.exe create` は登録の情報を作るだけなので、登録そのものは成功します。失敗するのは
`sc.exe start` のときで、SCM は決めた時間だけ応答を待ち、来なければエラー 1053 として
止めます。「登録できた」ことを確かめて先へ進むと、実機で初めて動かないと分かります。
実際、配布物の検査は登録の文字列を読むだけで、起動までは見ていませんでした。

サービスの形を保つには、SCM と話す wrapper を配布物へ入れることになります。
そのような wrapper は既存のもの（WinSW、NSSM など）を使うのが普通で、
どれも実行ファイルです。

私たちは「実行ファイルを配らない」と決めています（`scripts/package-agent.sh`）。
署名と配布の方式が決まっていない今、署名なしの実行ファイルを出せば、
受け取った側はそれが本物かどうかを確かめられません。

## 決定

Windows での常駐は、**タスクスケジューラ**で行います。Windows のサービスとしては
登録しません。

配布物には `install-startup.ps1` と `uninstall-startup.ps1` を入れます。
`Register-ScheduledTask` で、次の形の作業を登録します。

- 端末の起動時に開始する（`-AtStartup`）
- SYSTEM として動かす（利用者のログオンを待たない）
- 実行時間の上限を設けない（常駐するため）
- 異常終了したら、間を空けて上げ直す
- 二重に起動しない

止めるときは、まず `agent stop` で行儀よく終わらせ、終わらなければタスクを止めます。
タスクスケジューラの停止はプロセスを強制的に終わらせるだけで、Windows には
「行儀よく終われ」という合図がありません。送信の途中で強制的に終わらせても
送信待ちは消えませんが、毎回そうする理由もありません。

## 影響

- 「Windows のサービスとして動く」という約束をやめます。能力の一覧、#195、
  運用の文書から外します。約束を実装より先に置いたままにはしません。
- 求めていたもの（起動時の自動常駐、異常終了からの再開、停止、削除）は、
  タスクスケジューラで同じ水準を満たせます。満たせないのは「サービスの一覧に出る」
  ことだけで、それ自体は運用の要件ではありません。
- 実行ファイルを配らない決定は、そのまま保てます。
- 停止のために、行儀よく終わる合図を製品側に置きます（`agent stop`）。
  これは Windows に限った話ではなく、どの環境でも同じ仕組みで止められます。

## 見直す条件

次のどれかが起きたら、サービスの形を改めて検討します。

- 署名と配布の方式が決まり、実行ファイルを配れるようになったとき（P26）
- 導入先の規則で「サービスとして登録されていること」が求められたとき
- タスクスケジューラでは満たせない運用上の要求（サービスへの依存関係、
  復旧の細かい制御など）が出てきたとき
