# 打刻端末の常駐と実機の確認

現場に置く端末で常駐し、打刻をサーバーへ送り続けるための運用です。
実機を使わずに取り決めを試す手順は [guide/device-agent.md](../guide/device-agent.md) にあります。

このリポジトリに入っているのは、サーバーとの取り決めと、その取り決めを守る側の実装です。
装置のドライバを叩く部分と、Windows の実機で常駐させた確認は
含まれていません。何が確かめてあって何が確かめてないかは、
最後の[実機で確かめること](#実機で確かめること)にそのまま書いてあります。

## 動かす

登録してから常駐させます。

```bash
pnpm agent enroll --url https://staffweave.example --token-stdin
pnpm agent station
```

`station` は、読み取り装置と送信を 1 つのプロセスで持ちます。読み取ったカードは
その場で送らず、送信待ちへ積みます。積んだものは同じプロセスが送ります。

読み取りと送信を別のプロセスに分けると、常駐として登録した側だけが動き、
もう一方は誰も起動しない状態になります。実際にそうなっていました。

読み取り装置を付けない端末では、送信だけを常駐させます。

```bash
pnpm agent serve
pnpm agent queue --employee E001 --type clock_in
```

`queue` は送信待ちへ積むだけです。その場で送ろうとすると、回線が切れているあいだ
利用者を待たせることになります。

困ったときは状態を出します。

```bash
pnpm agent diagnose
```

秘密鍵と IC カードの指紋の鍵は出しません。診断は保守の人が現場で実行するため、
画面と端末の履歴に残ります。

## 送信待ちの持ち方

送れなかった打刻は、1 件を 1 ファイルとしてディスクへ書きます。

メモリだけに持つと、端末が落ちた時点で消えます。消えた打刻は誰にも見えないため、
あとから足すこともできません。

1 つのファイルへ追記しないのは、書いている最中に落ちたときに、行の途中で切れた
ファイルが残るためです。別々のファイルなら、壊れた 1 件を切り離して残りを送れます。

書き込みは一時ファイルへ書いてから名前を変えます。名前の変更は途中で終わらないため、
読み手が半端な内容を拾いません。

読めなかったファイルは捨てず、`.unreadable` を付けて残します。
中身を人が確かめて、手で入れ直せるようにするためです。`diagnose` が件数を出します。

## 送る順番

打刻は起きた順に送ります。1 件でも送れなければ、そこで止めて次の機会に回します。

飛ばして先へ進むと、サーバー側の連番が飛び、あとの打刻まで拒まれます。

サーバーが「その要求は受け取れない」と答えたものだけは、送信待ちから外します。
残しても同じ答えしか返らず、後ろの打刻が永久に出られなくなるためです。
外したことはログへ残します。

## 送れない間の間隔

送れない間は、試すたびに間隔を広げます。広げないと、切れている回線へ数秒ごとに出続け、
端末の電池と現場の回線を無駄に使います。

## ログ

1 行 1 件の JSON で書きます。秘密鍵・登録トークン・IC カードの識別子とその指紋・
署名は、書く側が忘れても値ごと伏せます。

端末のログは現場に残り、保守のときに人の目に触れます。「出さないよう気を付ける」では、
項目が増えたときに漏れます。

## Windows で常駐させる

配布物を作ります。

```bash
./scripts/package-agent.sh artifacts/agent
```

作られるのは、コンパイル済みの JS と、動かすのに要る他所の部品、
起動時の常駐として登録・削除するための PowerShell の手順です。

TypeScript のままは配りません。Node は `.ts` を読めず、置いただけでは起動しません。

他所の部品はまとめる時点で取り寄せ、同梱します。現場の端末は通信できないことがあり、
置いてから取り寄せる形にはできません。

Node.js そのものは同梱しません。実行ファイルも作りません。作ると、署名と配布の方式が
決まっていない今、署名なしの実行ファイルが出回ります。

配布物は、リポジトリを持たない端末でそのまま動きます。

```powershell
node agent\cli.js diagnose
```

登録は管理者として行います。起動するのは `agent/cli.js` です。

```powershell
.\install-startup.ps1 -NodePath "C:\Program Files\nodejs\node.exe" -AgentRoot "C:\StaffWeave\agent"
```

**Windows のサービスとしては登録しません。** タスクスケジューラで、端末の起動時に
始まる作業として登録します。サービスとして動くプロセスは Service Control Manager と
話す入口を持っている必要があり、`node.exe` も `agent/cli.js` も持っていません。
サービスの形を保つには、その入口を持つ実行ファイルを配ることになります。
理由と、選ばなかった案は
[decisions/0002-windows-residency.md](../decisions/0002-windows-residency.md) にあります。

利用者のログオンは待ちません。据え置きの端末は、誰もログオンしないまま置かれます。

落ちたときは間を空けて上げ直す設定にしてあります。上げ続けると、直らない不具合で
端末の電源を使い切ります。

止めるときは、まず行儀よく終わらせます。

```powershell
node agent\cli.js stop --store "C:\ProgramData\StaffWeave\agent.json"
```

タスクスケジューラの停止はプロセスを強制的に終わらせるだけで、Windows には
「行儀よく終われ」という合図がありません。強制的に終わらせても送信待ちは
消えませんが、送っている途中で切ると、サーバーが受理したかどうかの分からない
1 件が残ります。次に上げたときに送り直すので失われはしませんが、毎回そうする
理由もありません。`uninstall-startup.ps1` は、この順で止めてから外します。

登録を外しても、資格情報と送信待ちのファイルは消しません。送れていない打刻が
残っている可能性があるためです。

## Windows での資格情報の守り方

資格情報のファイルは、常駐を動かす利用者だけが読める場所へ置いてください。

Windows では、ファイルの権限ビット（POSIX の mode）を安全性の根拠にしていません。
`stat()` が返す値は実際の権限（ACL）を表さず、多くの場合そのまま `0o666` になります。
これを根拠に判断すると、正しく守られている資格情報を「他人から読める」と誤って断ります。

守るのは NTFS の ACL です。置き場を作るときに、次のように絞ってください。

```powershell
icacls "C:\ProgramData\StaffWeave" /inheritance:r /grant:r "SYSTEM:(OI)(CI)F" "Administrators:(OI)(CI)F"
```

絞れているかは、実機のチェックリストで確かめます。

## IC カードの読み取り装置

対応する標準インターフェースは **PC/SC** の 1 つだけです。
複数に広げると、どれも実機で確かめないまま増えます。
PC/SC は Windows（WinSCard）と Linux・macOS（PCSC-Lite）の両方にあり、
据え置きの打刻端末でいちばん行き渡っています。

生の識別子は端末の外へ出しません。サーバーへ送るのは一方向の指紋だけです。
データベースには指紋しか残らないため、その内容だけでは物理カードと結び付きません。

### 何がリポジトリの中にあるか

カードから識別子を読む擬似 APDU（`FF CA 00 00 00`）の送信、応答の状態語の判定、
同じカードの連続タップの扱い、装置が外れたときの開き直しは、リポジトリの中にあります
（`packages/agent/src/card/pcsc.ts`）。

PC/SC の装置へつなぐ受け渡しは、配布物へ同梱しています
（`agent/card/pcsc-winscard.js`）。利用者がコードを書く必要はありません。

装置のドライバを叩く部分だけは含めません。OS ごとに組み立てが要り、
Linux で組み立てたものを Windows へ配ることはできないためです。

### 読み取り装置を使えるようにする

端末で 1 回だけ、装置の部品を取り寄せます。配布物に手順が入っています。

```powershell
.\install-reader.ps1
```

入っていない端末で `station` を動かすと、この手順を案内して止まります。
黙って読み取りなしで立ち続けると、打刻できない端末が動いているように見えます。

別の受け渡しを使う端末では、その置き場を渡せます。

```sh
pnpm agent station --pcsc /opt/staffweave/pcsc-transport.js
```

形が合わない部品は、打刻の途中ではなく読み込みの時点で断ります。
途中で落ちると、端末の前の人が何が起きたのかを判断できません。

### カードを登録する

読み取り装置へカードを置いて登録できます。

```sh
pnpm agent card-register --token-file <path> --reader
```

`--reader` を付けなければ、識別子を手で入れます。手入力しか無いと、登録のときだけ
人がカードの番号を読み取って書き写すことになり、写した番号が端末の外に残ります。

### 実機がない場所

`createScriptedCardReader` を使います。あらかじめ与えた識別子を順に返すため、
登録から打刻までの流れを装置なしで通せます。

## 実機で確かめること

以下は、このリポジトリの検査では確かめていません。**実機がある環境で確かめてください。**
確かめていない項目は
[docs/product/capability-matrix.md](../product/capability-matrix.md) でも
`partial` として示しています。

### 物理の IC カード

- [ ] 配布物の `install-reader.ps1` で装置の部品が入り、`diagnose` が装置の名前を出す
- [ ] `card-register --reader` で、カードを置いて登録できる
- [ ] 登録したカードをかざすと、常駐している `station` が打刻を記録する
- [ ] 登録していないカードをかざすと、打刻されず、理由が端末へ出て、連番が進まない
- [ ] 失効させたカードをかざすと、打刻されない
- [ ] 同じカードを続けて 2 回かざしたとき、二重の打刻にならない
- [ ] 読み取り装置を抜き差ししても、常駐が落ちず、間を広げながら開き直す
- [ ] 端末のログに、カードの生の識別子も指紋も出ない

### Windows での常駐

登録・開始・停止・削除は CI の「Windows の常駐」でも通しています。実機で確かめるのは、
端末の再起動と、読み取り装置を付けた状態です。

- [ ] `install-startup.ps1` で `station` として登録でき、端末の起動時に始まる
- [ ] 登録した常駐 1 つだけで、カードの読み取りから送信まで完結する
- [ ] 端末を再起動すると、誰もログオンしなくても自動で上がる
- [ ] 送信待ちが残った状態で再起動しても、上がったあとに送られる
- [ ] `agent stop` で、決めた時間の内に行儀よく終わる
- [ ] 強制終了しても、送信待ちのファイルが壊れない
- [ ] `uninstall-startup.ps1` で登録を外せ、資格情報と送信待ちが残る
- [ ] 常駐を動かす利用者以外は、資格情報のファイルを読めない（`icacls` で確認する）
- [ ] リポジトリを持たない端末で、配布物の `node agent\cli.js diagnose` が動く

### 回線と時計

- [ ] 回線を抜いた状態でカードをかざすと送信待ちへ残り、つなぎ直すと送られる
- [ ] 回線を抜いた状態でかざしたあとサービスを再起動しても、送信待ちが残る
- [ ] 回線を抜いた状態で打刻を積み、つなぎ直すと送られる
- [ ] 送れない間、試す間隔が広がる
- [ ] 端末の時計を大きくずらすと、サーバー側で時計差として記録される
- [ ] 端末を交換したとき、古い端末を失効させれば打刻できなくなる

### 確かめた記録の残し方

上の項目を確かめたら、日付・端末の型番・OS の版・確かめた人を添えて、
運用の記録として残してください。この文書には書き足さないでください。
文書へ書くと、次に確かめ直したときに古い記録が残ります。
