# データの保持

どのデータをいつまで持つかを決めます。

自動で消す仕組みはありません。消すのは手で行います。
方針だけ先に決めておくのは、決めないまま溜め続けると、
あとから「いつまで持つ約束だったか」を誰も言えなくなるためです。

## 打刻した場所

既定では取りません。組織ごとに取ると決めたときだけ受け取ります
（`organizations.location_capture`）。

取ることは、打刻の画面で取る前に利用者へ伝えます。
取ったあとで説明しても、断る機会が無かったことに変わりはありません。

読めるのは本人と、その従業員の勤怠を見られる相手だけです。
位置情報が取れなくても打刻は記録します。位置情報を理由に打刻を失わせません。

## 消してはいけないもの

次のテーブルは追記のみで、書き換えと削除を DB が拒みます。

- `attendance_events` 打刻
- `attendance_calculations` 日次の計算
- `audit_logs` 監査記録
- `leave_ledger_entries` 休暇の台帳
- `employee_request_approvals` 段階承認の決裁
- `monthly_closing_snapshots` 締めた時点の集計
- `webhook_deliveries` 送信の履歴

消すには、行ではなくワークスペースごと消すことになります。
1 行だけを消す手段は用意していません。用意すると、
「消せない」という前提で組んだ他の仕組みが成り立たなくなります。

## 持つ期間の目安

法定の保存期間は事業者が確かめてください。製品は既定値を持ちません。

| データ | 目安 | 根拠 |
| --- | --- | --- |
| 打刻・計算・締め | 労務の記録として要る期間 | 事業者が決める |
| 監査記録 | 打刻と同じかそれ以上 | 打刻の正しさを説明する材料になる |
| 送信の履歴（Webhook） | 90 日 | 届かなかった通知を追うのに要る期間 |
| 諦めた通知（`webhook_outbox`） | 手で送り直すか、確かめてから消す | 消すと届かなかったこと自体が分からなくなる |
| ログイン失敗の記録 | 90 日 | 攻撃の傾向を見るのに要る期間 |
| 終わったセッション | 90 日 | 「どの端末から入っていたか」を追うのに要る期間 |
| 打刻した場所（`attendance_event_locations`） | 400 日 | 打刻を訂正できる範囲と同じ。訂正の根拠として要るのはそこまで |

## 消すとき

消す前に、必ずバックアップを取ってください。この command は控えを取りません。

```bash
pnpm backup
```

何をどれだけ消すかを、先に出します。既定では消しません。

```bash
pnpm retention -- --webhook-deliveries 90 --attendance-locations 400
```

出た件数を確かめてから、`--apply` を付けて実行します。

```bash
pnpm retention -- --apply --webhook-deliveries 90 --attendance-locations 400
```

消せる対象は次のとおりです。ここに無い表は消せません。表の名前を引数から
自由に受け取ると、打刻や計算のような消してはいけない表まで対象にできてしまいます。

| 引数 | 対象 | 期間を測る列 |
| --- | --- | --- |
| `--webhook-deliveries` | 送信の履歴 | `attempted_at` |
| `--attendance-locations` | 打刻した場所 | `captured_at` |
| `--login-attempts` | ログイン失敗の記録 | `updated_at` |

保持する日数は渡した値だけを使います。製品は既定値を持ちません。
渡さなかった対象は消しません。

消した件数は、消すのと同じトランザクションで監査へ残ります。
分けると、消した記録だけが残らない状態を作ります。

同じ引数で二度実行しても、二度目は 0 件になります。境界より前の記録が
すでに無いためで、やり直しても壊れません。

位置情報は打刻とは別の表に持ちます。消しても打刻は残ります。
同じ行に持つと、位置情報を消すために打刻の行へ触れることになり、
追記のみという取り決めと衝突します。

`webhook_outbox` の諦めた通知は、この command では消しません。
消すと「届かなかったこと」自体が分からなくなります。
手で送り直すか、確かめてから個別に消してください。

## 退職者の扱い

従業員の行は消しません。消すと、その人の打刻と計算が参照先を失います。

設定の画面から、その従業員を **退職にする** を押してください。1 つの操作で
次がまとめて行われます。手順を分けると、どれかを忘れたことに誰も気付けません。

1. 状態を `retired` にする
2. その利用者のセッションをすべて閉じる
3. その従業員の IC カードを失効させる

理由は必ず入れます。理由の無い変更は、監査から意図を読み取れません。
変えた内容と理由、閉じた件数は監査へ残ります。

**休止**（`suspended`）はセッションだけを閉じます。カードは失効させません。
休止は戻ることが前提で、戻るたびに配り直すのは運用の負担にしかならないためです。

打刻端末は失効させません。端末は拠点に属し、従業員には紐づきません。
誰が辞めても、その拠点の端末は動き続ける必要があります。

本人の記録は、上の保持期間のあいだ残ります。
