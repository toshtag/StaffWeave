# できること

いま実際に動くものだけを並べます。

動くことと、安心して本番で使えることは別です。労働法令に合っているか、
止まらずに動くか、脆弱性が無いかは保証しません。

リリース候補の条件は満たしていますが、実機・第三者・試行運用の確認が済んでいません。
正式なリリースタグはありません（[checklist.md](../release/checklist.md)）。

## 動くもの

### 組織と利用者

- ワークスペース、組織、拠点、部門、従業員の登録と一覧
- メールアドレスとパスワードによるログイン、セッション、ログアウト、パスワードの変更
- 本人によるログイン中の端末の一覧と、個別・一括のログアウト
- ロールによる権限制御（ワークスペース管理者 / 組織管理者 / 従業員）
- 日本語と英語の切り替え
- 雇用元と受入組織の契約、配属、勤務先別の閲覧権限と外部承認者

### 打刻と勤務時間

- 本人による出勤・退勤・休憩の打刻と当日の状態表示（追記のみ・二重送信防止・監査記録つき）
- 日付をまたぐ勤務の一日としての扱い。夏時間の切り替わる日もずれません
- 1 日に複数の勤務区間（中抜け・分割シフト・呼び出し勤務）。区間の間は勤務時間に数えません
- 画面の時刻は拠点の時間帯で表示・入力します。基準のタイムゾーンを画面に出します
- 打刻の修正・取消・追加（理由必須、元の記録は残り、変更前後を追える）。
  400 日前まで遡れます。締めた期間は直せません
- 勤務パターンと勤務予定の登録
- 勤務周期による勤務予定の生成（週休 3 日・2 勤 2 休など、曜日を前提にしない）
- 実労働・休憩・所定内外・深夜帯の決定的な計算（入力版・ルール版・根拠つき）
- 版管理された勤務区分（所定時刻、複数の固定休憩、自動休憩、みなし時間、深夜帯の上書き、
  中抜けの扱い、シフト属性と色）
- 法定内外、法定休日と法定外休日、深夜時間外、深夜休日、遅刻・早退・始業前・終業後の計算。
  法定内外の閾値は事業者が設定します。設定するまでは計算せず、未設定として示します
- 適用開始日つきの計算規則。過去の集計は当時の版のまま残ります
- 労働形態の割当（通常・フレックス・裁量・変形）。制度ごとの値は設定が必要です
- 休暇・欠勤を「その日の状態」として記録し、分数として集計する
- 休暇の台帳（付与・取得・失効・手当て・取消を追記で積む）。残数は保存せず、
  任意の時点の値を台帳から組み立てます。期限の近い付与から先に消化します
- 取得の単位と失効までの月数は事業者が設定します。設定するまでは適用しません
- 勤続の段ごとの付与規則と、それに従った自動付与・一斉付与・CSV 取込。
  段を置かないかぎり 1 分も付与しません。同じ日への二重付与は止まります
- 自動付与は日次の command が動かします（`pnpm leave:grants`）。休暇種別ごとに
  有効にし、始める日を決めます。止まっていた期間は次の実行で追いつきます。
  動かす前に、次の対象の日と人数を設定の画面から確かめられます
- 休暇管理簿（期首・付与・消化・失効・期末）と、失効の予定
- 有効期間付きの制度切り替え

### 申請と確定

- 日次の申請・承認・差し戻し・取消と、その履歴
- 組織が定義する申請種別（休暇・残業・休日出勤・打刻修正・その他）と、区分ごとの入力の要否
- 1〜4 段の承認、差し戻し、出し直し、取消、代理。段数は提出時の定義を写して固定します。
  あとで定義を変えても、進行中の申請の経路は動きません
- 申請・承認・差し戻し・取消・代理承認を、製品内の通知として本人と承認者へ届ける。
  通知の正本は DB に残ります
- 承認しきった休暇の申請を、その場で台帳へ反映する
- 承認しきった残業・休日出勤・打刻修正の申請を、日次の計算へ効かせる。
  残業は申請した上限時刻までを認定し、超えた分を分けて出します。
  休日出勤は承認のある分と無い分を分けます。打刻修正は、元の打刻を残したまま
  効いた打刻を差し替えます。締め済みの期間を含む申請は、承認そのものを断ります
- 月次の集計（日次から導く）と、締める前の確認（退勤していない日・承認待ち・差し戻し）
- 長時間労働の警告。1 か月と複数月平均の上限は計算規則の版が持ちます。
  上限を置かないかぎり警告は出さず、置いていないことを画面で示します
- 週・フレックスの清算期間・変形労働の対象期間の集計と、総枠との差。
  週の開始曜日は計算規則の版が、清算期間と対象期間は労働形態の割当が決めます。
  設定が無い区切りは出しません
- 月次締めと締め解除、確定後の編集制御
- 締めた時点の集計の固定。締めたあとに訂正しても、給与へ渡した値は動きません
- 設定を直したあとの再計算。締めた月は動かしません
- 確定後の変更・大量修正・端末時計差・連番欠落・重複打刻の検出と、根拠つきの表示・CSV 出力

### 端末と観測

- スマートフォン向けの打刻画面（オフライン待機・自動再送・冪等受理）
- 打刻した場所の記録。組織ごとに取ると決めたときだけで、既定は取りません。
  取ることは打刻の画面で先に伝えます。取れなくても打刻は残します
- 打刻端末の登録・失効と、署名付きイベントの受理（連番・時計差・受信記録つき）
- 端末で常駐する Agent。送れなかった打刻をディスクへ残し、順に送ります。
  送れない間は間隔を広げ、ログの秘密は書く側が忘れても伏せます
- 配布物の生成（コンパイル済みの JS と、動かすのに要る部品を同梱）と、
  Windows で起動時に常駐させ、外す手順
- 端末シミュレーター（実機なしで取り決めを確認できる）
- IC カードの指紋の登録・失効と、カードイベントの受理（生の識別子は送らず保存もしない）。
  読み取り装置は OS ごとに違うため同梱しません。取り決めと検証用のアダプターがあります
- PC セッションの観測記録の受理と、打刻との食い違いの提示（自動確定はしない）。
  OS から自動で送る常駐サービスはありません

詳細は [device-agent.md](device-agent.md)。

### 外部連携と運用

- CSV の入出力、給与連携向けの汎用出力、API キーとスコープ
- Webhook の送信・署名・再送・諦めた通知の置き場と、人による送り直し。
  間隔は試行のたびに広げ、送り直しても同じ答えしか返らないものは打ち切ります
- 外部連携を作るための connector SDK
- バックアップと復元。書き出して戻したものが元と同じであることを毎回確かめます
- 休暇の自動付与を動かす日次の command（`pnpm leave:grants`）。
  cron などから 1 日 1 回呼びます。1 日に何度呼んでも結果は変わりません
- デモ用データ

### 設定の画面

上でモジュールを切り替え、左でその中の設定を選びます。

- 組織・拠点・部門・従業員・閲覧範囲
- 勤務区分・計算規則の版・労働形態
- 休暇種別・休暇の台帳
- 申請種別と承認経路
- 月次の集計と、締める前の確認
- API キー、自分のセッション

一覧・写して作る・CSV は同じ形です。見られない設定は入口ごと出しません。
従業員・勤務区分・申請種別・休暇の付与は CSV でまとめて入れられます。
1 行でも読めなければ 1 行も取り込まず、読めなかった行を位置つきで返します。
取り出しは 2 通りあります。画面に見えているとおりの CSV と、取込へそのまま
戻せる CSV です。前者は表示の言語で出し、後者は機械の見出しと値で出します。

詳細は [integrations.md](integrations.md) と [operations/backup.md](../operations/backup.md)。

## まだ無いもの

- 端末・IC カード・Webhook・契約・配属の設定画面。API では扱えます。
  （勤務パターン・勤務周期・勤務予定・閲覧範囲は、設定の画面から扱えます。）
- 招待・パスワード再設定・メールアドレスの変更。管理者が作り、初回のパスワードを渡す運用です。
- MFA と SSO。
- 実機の IC カード読み取り装置と、Windows 実機での端末再起動の確認。
  作る側は揃っていますが、実機では確かめていません。
  読み取りと送信は 1 つの常駐（`station`）にまとまっていて、PC/SC の受け渡しも
  配布物に入っています。端末では、装置の部品を 1 回だけ取り寄せます。
- 端末の自動更新。配布物を置き直して入れ替えます。
- 公開デモ、Row-Level Security、メトリクスとアラート。

どの順で作るか、個々の課題がいまどこまで進んでいるかは、GitHub の Issue を見てください。
